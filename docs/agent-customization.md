# 为每个人定制 agent：底座 + 档案 + 模板

状态：设计稿。2026-10-24。
目标：一句话说清产品——**「一个能干活的基础 agent，加上属于你的定制。」**

---

## 0. 一句话定位

> **底座是「引擎」，档案是「人格」，模板是「可分享的档案」。**

- 底座（Base）：保证「能用」。
- 档案（Profile）：保证「像你」。
- 模板（Template）：让「像你」可以复制、分享、复用。

---

## 1. 为什么这样分层

三个产品约束，决定了必须分三层：

1. **每个人要「自己的 agent」** → 需要一层「每个用户独立」的配置。
2. **团队只能维护一份代码** → 需要一层「共享、稳定」的底座。
3. **定制不能把底座改坏** → 需要「底座对档案一视同仁」的边界。

如果只做「一份可改代码的 agent」，结果是：要么用户改坏、要么团队无法维护。
如果只做「一份固定 agent」，结果是：所有人都一样，没有「定制」。
**答案就是：一份底座 + N 份档案。**

---

## 2. 三层模型

| 层 | 是什么 | 谁维护 | 变多快 | 类比 |
|---|---|---|---|---|
| **底座** | 对话循环、工具执行、审批门、模型适配、Skill/插件宿主、持久化、UI 骨架 | 团队（+ RSI 人审） | 慢 | 操作系统 |
| **档案** | 名字、语气、默认模型、默认工具/权限、默认技能、主题、常用工作流 | **每个用户各一份** | 快 | 用户配置 |
| **模板** | 预置或导出的档案 | 团队/社区 | 中 | 配置包 |

> 底座是「模板」（可复用的引擎），档案是「实例」（每个人的那一份）。
> 「把底座作为模板」= **用不同档案实例化同一个底座**。

---

## 3. 底座边界（铁律）

> **档案只能「加减默认值」，不能关掉底座的安全与恢复能力。**

| 必须在底座（不可定制掉） | 可进档案（每人可调） |
|---|---|
| 对话循环、流式、取消 | 名字、语气、系统提示 |
| 工具执行 + 审批门 | 默认模型、推理强度 |
| 密钥、沙箱、单实例锁 | 默认工具集、权限模式 |
| 崩溃恢复、数据持久化 | 默认技能、插件 |
| 版本/回滚/审计 | 主题、字号 |
| — | 常用工作流、快捷指令 |

**为什么**：如果档案能改「审批门」或「回滚」，那「为每个人定制」就等于「为每个人定制一个不安全的 agent」。

**具体规则**：
- 档案不能禁用审批（`approval` 永远在底座）。
- 档案不能把权限从 `read-only` 提权到 `full`（只能收紧，不能放开）。
- 档案不能改密钥存储、单实例锁、恢复逻辑。
- 档案损坏 → 回退默认档案，底座照常启动。

## 4. 档案 Schema

```json
{
  "id": "profile-xxx",
  "name": "小助",
  "version": 1,
  "updatedAt": "2026-10-24T04:00:00+08:00",

  "persona": {
    "tone": "简洁、直接",
    "systemPrompt": "你是我个人的工作助手，优先给结论，再给理由。",
    "language": "zh-CN"
  },
  "model": {
    "channel": "gc",
    "model": "deepseek-v4",
    "reasoningEffort": "medium"
  },
  "tools": {
    "enabled": ["read_file", "write_file", "browser"],
    "permissionMode": "workspace-write"
  },
  "skills": ["check-web", "write-weekly"],
  "preferences": { "theme": "dark", "fontSize": "medium" },
  "workflows": [
    { "name": "周报", "prompt": "把这周的对话整理成周报" }
  ]
}
```

### 字段说明

| 字段 | 作用 | 注入到 |
|---|---|---|
| `name` | 显示名 | 侧栏 / 标题 |
| `persona.systemPrompt` | 追加到系统提示 | `embuddies-runtime.mjs` 的系统消息 |
| `persona.tone` | 语气约束 | 同上（拼进系统提示） |
| `model.*` | 新对话的默认模型 | `handlePromptStream` 的 `channel` |
| `tools.enabled` | 默认启用的工具 | `getToolDefinitions` 过滤 |
| `tools.permissionMode` | 默认权限（只能收紧） | `permissionMode` |
| `skills` | 默认挂载的技能 | `resourceStore.buildRuntimeContext` |
| `preferences` | 主题/字号 | `preferences.mjs` |
| `workflows` | 快捷指令 | 输入框旁的快捷入口 |

---

## 5. 存储、校验、版本

### 存储
- 位置：`dataRoot/profile.json`（当前档案）+ `dataRoot/profiles/<id>.json`（历史版本）。
- 复用 `preferences.mjs` 的模式：原子写、白名单、损坏回退。

### 校验
- 未知键 → 拒绝（防注入）。
- 枚举值 → 白名单（`tone`、`permissionMode`、`theme`、`fontSize`）。
- 字符串长度上限（`systemPrompt` ≤ 4000）。

### 版本
- 每次更新 → 存一份 `profiles/<id>.json`（带 `version`）。
- 支持「回滚到上一版」（和 Skill 资源版本一致）。

## 6. 注入点（改哪里）

| 档案字段 | 代码位置 | 改法 |
|---|---|---|
| `persona` | `embuddies-runtime.mjs` 第 962 行系统提示 | 在基础提示后追加 `\n${persona.systemPrompt}` |
| `model` | `application-service.mjs` `handlePromptStream` | 新对话默认用 `profile.model`，已有对话用对话自身的 |
| `tools` | `embuddies-runtime.mjs` `getToolDefinitions` | 按 `profile.tools.enabled` 过滤 |
| `permissionMode` | `handlePromptStream` | 默认用档案值；只允许收紧 |
| `skills` | `resourceStore.buildRuntimeContext` | 默认挂载档案里的技能 |
| `preferences` | `preferences.mjs` | 已接通 |

> 原则：**档案是「默认值」，对话是「当前值」**。新对话继承档案，对话内可临时覆盖（不写回档案，除非「设为默认」）。

## 7. 模板机制

三层能力：

1. **导出 / 导入**
   - 导出：当前档案 → `.embuddies-agent`（JSON）。
   - 导入：校验 → **新建**档案（不覆盖现有）+ 可切换。

2. **内置模板**
   - 写作助手 / 代码助手 / 研究助手 / 运营助手。
   - 每个 = 一份预置档案。

3. **存为模板**
   - 「把我的配置存为模板」→ 分享给同事/社区。
   - 模板 = 档案的「种子」，实例化后独立修改，不反向影响模板。

## 8. 交互

### 设置面板「我的 agent」
- 名字、语气（预设 + 自由输入）
- 默认模型（下拉，来自 `configStore`）
- 默认工具（开关列表）
- 默认技能（从资源库勾选）
- 主题/字号（已有）
- 常用工作流（增删）

### 对话内
- 输入框上方显示当前档案名（`小助`）。
- 「设为默认」：把当前对话的模型/权限/技能写回档案。
- 快捷指令：`/周报` 触发 `workflows`。

## 9. 四阶段落地

| 阶段 | 交付 | 验收标准 |
|---|---|---|
| **P0 底座验收** | 零配置可用清单 | 新用户 3 步内发出第一条消息并拿到回答 |
| **P1 档案层** | 档案存储 + 设置面板 + 导出/导入 | 改默认语气/模型/技能 → 新对话生效 |
| **P2 模板层** | 内置模板 + 存为模板 | 从模板新建 → 预填 → 可改 |
| **P3 对话驱动** | `propose_profile_change` 工具 | 对话里说「以后简洁点」→ 提议 → 确认 → 生效 |
| **P4 代码级（可选）** | 复用现有 RSI | 只有「需要新能力」时才走代码 |

**P0 最重要**：底座不「能用」，「为每个人定制」就是空中楼阁。

---

## 10. 底座验收（P0 清单）

- [ ] 全新安装，不配模型也能看到清晰引导（一步到可工作状态）。
- [ ] 新建对话 → 发消息 → 流式回答。
- [ ] 调一次工具（读文件/搜索）→ 审批卡 → 批准/拒绝。
- [ ] 装一个 Skill → 在对话里被调用。
- [ ] 装一个插件（MCP）→ 工具可用。
- [ ] 断网/模型 500 → 报错清晰、历史不丢。
- [ ] 强制退出 → 重开，对话和历史都在。
- [ ] 打包版双击可启动。

> **当前最大风险**：底座目前必须配置 API Key 才能用。P0 需要决定：是否内置一个默认可用通道，或把引导做到 30 秒内完成配置。

## 11. 与自进化的关系：两个循环

| 循环 | 对象 | 速度 | 门槛 |
|---|---|---|---|
| **底座进化** | 底座代码 | 慢 | 人审 + 证据（RSI） |
| **档案进化** | 档案配置 | 快 | 即时（偏好/Skill/对话） |

**「为每个人定制」= 档案进化跑在每个人身上；「底座持续变好」= 底座进化由团队/RSI 统一推进。**

这解决了一个根本矛盾：用户要「我的 agent 只属于我」，团队要「只维护一个底座」。答案：**一份底座 + N 份档案**。

---

## 12. 风险与开放问题

1. **底座可用性**：不配模型不能用 → 必须解决（内置渠道或极简引导）。
2. **档案膨胀**：字段过多会变复杂 → 只放「高频、有价值」的定制项。
3. **档案例外**：用户想「改代码级行为」→ 走 P4（RSI），不走档案。
4. **多档案**：要不要支持「一个用户多个 agent」（工作/生活）？建议 P2 后再考虑。
5. **同步**：档案要不要跨设备同步？涉及隐私与账号体系，暂不做。

---

## 13. 不做的事（先划清）

- 不做「市场/商店」（P2 只做内置 + 文件导入导出）。
- 不做「档案里写代码」。
- 不做「档案改安全/审批/密钥」。
- 不做「一个用户多档案」（首版）。
- 不做「云端同步」。
