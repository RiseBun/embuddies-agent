# embuddies 桌面伙伴设计 v0.1

状态：产品与交互设计；随附本地可点击原型。尚未接入真实模型、记忆服务、电脑观察或 Agent。现有安装包不受本次设计影响。

## 本轮交互修订

- 开场只显示“你好，怎么称呼你？”和输入框。删除演示场景栏、重置按钮、跳过按钮，默认不展示状态小字、球球旁白和解释性段落。
- 用户输入“跳过”“直接聊”即可结束相识；输入“跳过这个问题”只跳过当前问题。已跳过或完成相识的用户刷新后进入再次见面，不反复问称呼。
- 顶栏只保留品牌，移除“记忆”和“偏好”按钮及数量。说“你记得我什么”查看记忆，说“相处方式”调整偏好；场景中的必要入口仍保留。
- 记忆来源只保留按需查看的入口；详细说明放在设计文档中。错误和示例标识仍明确呈现。
- 启动时原环形球球做一次“蓄力 → 跃起 → 落地压缩 → 小回弹 → 站稳”，约 1.15 秒，最高离地约 64 个逻辑像素。
- 点击球球重放轻跳；鼠标接近时轻微歪头，输入与确认记忆时点头，眼睛跟随鼠标并偶尔眨眼。不同动作互斥，只有真实交互触发大动作，不循环跳跃。
- 跳跃使用变换动画，不改变对话或输入框布局。落地影随离地高度改变大小和透明度，不增加面部元素。
- 系统低动态偏好和“减少动作”可即时停止并抑制后续动画。原型窗口隐藏后暂停待机动作。
- 下文场景中的长文案保留为行为规格，前端使用本轮精简文案。

## 目标

让用户感到：它记得我、理解眼前的事、愿意主动帮助，而且我能够纠正它。

第一版以“相识 → 确认记忆 → 重启后承接 → 适时主动 → 可纠正与忘记”为完整闭环。复杂任务交给用户选择的本机 Agent。球球的形象与动作、记忆和互动体验属于 embuddies。

核心判断：记忆准确度、主动建议的相关性和交互响应，比动作数量和主动发言次数更重要。

## 界面与视觉

- 默认入口：透明桌面球球。单击出现轻量对话，双击打开完整助手面板；拖动越过阈值后不触发点击，原生宿主处理拖动。
- 初次安装打开相识对话；有历史后恢复上次窗口模式。跳过相识即可直接使用。
- 助手面板围绕对话、待确认事项、正在执行的任务组织。资源与工作区在高级能力层，不要求用户先配置。
- 对话顶部只显示品牌；真实互动状态用于可访问反馈。记忆与偏好通过对话及相关场景按需进入，可以查看来源、改正、忘记。
- 原环形 SVG 保留。中央伙伴与消息头像分别使用独立实例，不移动启动球节点。
- 色彩：白色 #ffffff、背景 #fbfbfd、正文 #20242d、边线 #e4e7ee、品牌薄荷 #138879、危险操作 #b65b50。状态同时有文字，不仅依赖颜色。
- 字体：Segoe UI Variable / Microsoft YaHei UI；正文 15–16px，主对话 22–28px。操作按钮 34–38px，窄屏和触摸放大点击区。
- 圆角以 6px 为主；输入框稍大。视觉重点只给球球和当前一句话，不铺设仪表盘、卡片墙或装饰渐变。
- 眼睛短暂跟随鼠标、点击后回应；默认不连续跳跃。低动态模式使用静态姿态。首个本地交互响应目标小于 100ms，不等模型。

## 场景一：首次相识

开场：“你好，我是 embuddies。我们先认识一下？也可以直接告诉我想做什么。”

最多依次了解三个问题，中途随时跳过：

1. 称呼：“我该怎么称呼你？”
2. 近期目标：“最近主要在忙什么？”
3. 打扰偏好：“什么时候，你希望我主动开口？”

称呼和目标的回答先作为会话内容；随后就地出现记忆候选：

> 下次还这样称呼你吗？
> 记住 / 只在这次聊；也可输入“跳过”

只有明确点击“记住”或用户明确要求“记住……”后，事务提交成功才反馈“记住了”。自由文本中的偏好、个人事实默认生成待确认候选；模型不得直接写长期记忆。

打扰偏好选择后直接保存该明确选择，提供三个清楚的选项：

- 等我叫你：没有主动对话；用户已请求的审批、任务结果仍正常送达。
- 偶尔提醒：在相关事项需要关注时给出非抢焦点提示。
- 更主动一点：增加有依据的启动承接与相关建议，仍受频率和场景限制。

没有选择时采用“等我叫你”，不能将跳过当成同意观察电脑或主动通知。

允许随时输入普通目标。比如“先打开记事本”应立即退出相识流程进入能力路由，后续可以再认识；原型仅演示对话和记忆，不执行软件操作。

## 场景二：再次见面

本地读取已确认偏好和一条相关经历，先判断是否需要开口：

- 新用户或无相关经历：简短问候或安静等待，不编造共同经历。
- 有相关目标且用户允许主动：例如“你上次提到在做 embuddies。今天想从哪里开始？”
- 存在持久化的未完成任务：展示任务名称及真实状态，按钮为“查看记录 / 继续 / 暂时不管”。
- 仅有目标，没有任务：只问是否继续讨论，不能显示“继续执行”或声称任务正在运行。
- Agent 不可用：仍可读记忆、对话记录、设置与使用本地入口。具体任务显示不可用原因，球球不变为整个软件离线。

每次启动最多一个主动对话提示。重复启动不能绕过频率限制。同一个依据的提示不重复弹出。自动问候不进入记忆，避免记忆循环自我强化。

## 场景三：记忆与用户模型

用户模型由可核对的认识组成。它不是人格评分或隐藏的心理档案。

### 数据分类

| 类型           | 例子                   | 形成方式                         | 失效策略                                      |
| -------------- | ---------------------- | -------------------------------- | --------------------------------------------- |
| 确认的个人信息 | 称呼                   | 用户直接确认                     | 改正或忘记前保留                              |
| 确认的偏好     | 回答简短、常用编辑器   | 明确设置或确认候选               | 按范围生效；新确认覆盖旧值                    |
| 当前目标       | 正在推进 embuddies     | 用户确认                         | 30 天未确认时标为待复核；不自动延续为当前目标 |
| 共同经历       | 上次确认了一个设计决定 | 用户确认摘要，关联真实会话或任务 | 与原始记录关联；不能将失败记为成功            |
| 临时情境       | 今天开会，先别打扰     | 明确指令或已授权的短期信号       | 本次会话、设定时间或次日过期                  |
| 待确认认识     | 可能偏好简短回复       | 模型提议，附原文来源             | 不作为长期事实注入；7 天未处理过期            |
| 电脑事实       | 应用启动路径、授权目录 | 本地发现并记录来源               | 使用前检查；不升级为个人偏好                  |

每条记忆至少包含：

```ts
type Memory = {
  id: string;
  subjectId: string; // 当前本地用户配置，不按模型推断真实身份
  kind: "identity" | "preference" | "goal" | "episode" | "temporary";
  key: string; // 例如 preferred_name、response_style
  value: string;
  status: "candidate" | "confirmed" | "superseded" | "forgotten";
  scope: "user" | "project" | "session";
  scopeId?: string;
  source: {
    type: "user_message" | "setting" | "confirmed_summary";
    conversationId?: string;
    messageId?: string;
    evidence?: string; // 必要的最短原文，不复制整个对话
  };
  createdAt: string;
  updatedAt: string;
  confirmedAt?: string;
  expiresAt?: string;
  replacesId?: string;
  revision: number;
};
```

### 写入、检索、冲突

1. 会话中出现相关内容，模型仅返回候选和来源。
2. 应用校验来源、范围、重复和敏感信息。密码、密钥、验证码不进入普通记忆。
3. 交给用户确认；用户明确“记住”可直接提交。
4. 提交记忆与变更记录的事务后再确认成功。失败显示“还没保存”，保留待处理内容。
5. 每次请求只读取必要的称呼、偏好、当前目标和相关经历；保留来源标记，不把记忆内容拼成高权限系统指令。
6. 用户当下明确指令优先于长期偏好；项目偏好只在该项目内生效。新确认取代同一范围的冲突记录，不让两个矛盾值同时检索。

第一版用结构化键、范围与关键词检索，限制最多 12 条 / 约 1,500 tokens；超限优先保留当次相关信息。不先引入向量数据库。容量变大后根据实际检索错误决定是否增加语义检索。

网页、文件、外部 Agent 输出只能作为外部资料。它们不能自行确立用户身份、记忆确认或授权。

### 用户控制

- “你记得我什么？”打开记忆面板，按个人信息、偏好、目标和经历分组。
- 每条显示确认状态与来源，可改正、忘记；尚未确认项可确认或忽略。
- “这次不要记住”使本次会话不生成长期候选；现有记忆是否使用由单独开关控制。
- “忘掉这条”立即从检索、摘要缓存和待同步内容移除，变更记录仅保留不含正文的删除标记。
- 默认的忘记操作不声称删除原始聊天。需要时另提供“同时删除来源对话及其派生记忆”，说明影响并整体处理。
- 备份可能含旧内容；恢复时应用删除标记，不能让遗忘的记忆复活。备份保留期和完全清除入口需要在正式实现中定义。
- 导出、全部清除、暂停记忆都在记忆管理中，不藏在模型配置里。

## 场景四：主动互动

主动提示必须由事件触发，并附内部依据。例如：首次启动、任务状态变化、用户指定时间、授权目录的相关变化。没有变化就保持安静，不让模型定时找话题。

```text
事件 → 检查授权与打扰偏好 → 检查相关性和时效
     → 去重、冷却与额度 → 生成简短建议 → 再检查当前情境 → 呈现
```

默认规则是可调整的产品起点，需要试用验证：

- 未选偏好：不主动开口。
- 偶尔提醒：主动对话最多 1 次 / 小时、3 次 / 本地自然日。
- 更主动一点：主动对话最多 1 次 / 30 分钟、6 次 / 本地自然日。
- 额度与已展示事件 ID 持久化，重启不重置。生成但未展示不消耗额度；展示后原子记录。
- 演示原型手动触发情境，不实现真实时间调度，面板明确标识。
- 用户已请求的结果、审批、报错作为任务通知独立处理并去重；安静模式不丢失这些消息，不自动播报或抢焦点。
- 系统忙碌、用户设置暂停或已授权的全屏/勿扰信号成立时延迟主动对话。过期建议直接丢弃，不集中补发。
- 同类建议连续两次被明确忽略后暂停该类建议 7 天；用户可随时恢复。
- “稍后”提供明确时间；“今天安静”持续到用户时区下一日；另有显式“恢复提醒”。没有回复不视为授权执行。
- 不根据打字频率、窗口标题擅自判断情绪或健康，也不把沉默解释成需要更多提醒。

主动建议和自主行动分别授权。提出“要不要打开项目”不代表已经打开；整理、修改、发送等动作进入对应权限流程。

## 球球状态与动作

| 状态       | 动作与呈现                         | 实际依据             |
| ---------- | ---------------------------------- | -------------------- |
| 待机       | 静态环形，偶尔眨眼                 | 本地界面可用         |
| 回应       | 眼睛看向输入方向，轻微短促抬起     | 用户点击或输入       |
| 读取       | 短暂收拢目光                       | 真实读取请求未结束   |
| 等待 Agent | 安静等待，显示执行者名称           | 已接受的外部任务     |
| 等待你     | 看向确认按钮，一次轻提示           | 实际审批或待确认问题 |
| 完成       | 一次短促回应，再回待机             | 已持久化的完成事件   |
| 出错       | 停止等待动作，提供可执行的处理入口 | 真实失败事件         |

不根据任意计时器伪造“思考中”或“完成”。断线、无模型或模型失败时，本地姿态、菜单、已存记忆和历史照常可用。

## 实施与验收顺序

### A. 相识与可控记忆

- 相识可以跳过，普通任务输入可以中断相识。
- 候选未确认前不会在下一次会话被当成已知事实。
- 保存失败不反馈成功；重启后称呼、偏好与目标准确恢复。
- 纠正覆盖旧值；忘记后所有检索和摘要均不引用旧值。
- 暂停记忆后没有新的候选；敏感内容不进入记忆。
- 外部网页或 Agent 文本不能确认记忆或改变授权。

### B. 再次见面与主动

- 欢迎内容引用真实来源；没有真实任务不提供假恢复入口。
- 安静、全屏、冷却、额度、过期与去重规则在重启后仍有效。
- 关闭主动对话后任务结果和审批仍可查看；不抢焦点。
- 连续启动不会连续问同一个问题；不在离线时清空记忆。

### C. 真实任务承接

- 按用户选择连接本机 Agent；记录会话、任务和执行者。
- 结果成功与保存成功分开检查，经历摘要只反映真实结果。
- 中断恢复核对执行记录，不自动重放副作用。
- 当前电脑观察采用按范围授权；不因为开启记忆就默认扫描文件或监视屏幕。

## 原型使用与局限

打开同目录 `prototype.html`。首次相识可输入称呼和目标，逐条确认记忆；输入“跳过”或“直接聊”可直接开始。再次打开时承接已确认的信息。输入“你记得我什么”查看并管理记忆，输入“相处方式”调整偏好；“我回来了”“重新认识一下”“主动找我聊聊”用于通过对话体验其他场景。界面没有演示导航栏和跳过按钮。

示例资料不自动写入已确认记忆。原型只将用户主动在演示中确认的信息保存到浏览器隔离键 `embuddies-companion-prototype:v1`；每条记忆可以在记忆面板忘记。开发验证使用隔离浏览器配置并单独清除演示数据。没有网络请求、真实软件启动、真实 Agent 调用或电脑扫描，该存储不代表正式软件的安全和可靠存储实现。
